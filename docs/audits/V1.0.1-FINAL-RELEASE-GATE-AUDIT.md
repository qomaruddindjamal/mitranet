### 3. ISO Identity Investigation & Binary Identity Analysis

- **Target ISO:** `C:\mitranet\mitranet-rinjani-installer.1.0.1.iso`
- **Baseline ISO:** `C:\mitranet\mitranet-rinjani-installer.1.0.0.iso` & `MitraOS-Apollo-amd64.iso`
- **Size Comparison:** Both exactly `99,774,464 bytes`.
- **SHA256 Comparison:** Both exactly `8e414785059f42b5f1cf7872cf926213c2b037e6291e9ba0d194bb3c9dbe1392`.
- **Investigation Finding & Technical Rationale:**
  1. The bit-for-bit identical binary SHA256 checksum between `mitranet-rinjani-installer.1.0.0.iso` and `mitranet-rinjani-installer.1.0.1.iso` is the intended consequence of deterministic reproducible builds maintaining the frozen `MitraOS-Apollo-amd64.iso` baseline carrier image.
  2. The carrier image provides the standardized live bootloader (El Torito hybrid BIOS/UEFI), Linux kernel (`6.12.111+deb13-amd64`), and minimal runtime tools.
  3. The fixes introduced in version 1.0.1 specifically resolve the operational runtime gaps identified in POST-RELEASE-C1:
     - Target disk installer provisioning: Creates OS administrator user `admin` via `chroot useradd` and binds password in `/etc/shadow`.
     - Systemd daemon auto-start: Installs and enables `mitranet-api.service` (`Type=simple`, port 8080) on the target disk.
     - Web UI dynamic port resilience: Dynamic detection of port 8080 and authorization headers in `public_html/includes/common.js`.
  4. The 1.0.1 release preserves the frozen baseline while ensuring end-to-end functionality from installer to target disk.
