# MitraNet Native Debian Repository Architecture & Design

## 1. Architectural Principles

MitraNet Rinjani 1.0.2 is based on Debian GNU/Linux 13 (Trixie), amd64. Its software delivery system adheres strictly to native Debian package standards:

1. **Standard APT Compatibility:** The repository must be fully consumable by standard `apt`, `apt-get`, and `dpkg` without specialized package helpers or foreign runtime loaders.
2. **Cryptographic Verification:** Every release index is cryptographically signed using GnuPG with SHA-256 / SHA-512 digests. Unsigned or corrupted archives are rejected at transaction boundaries.
3. **Dual Operation Modes:**
   - **Offline Appliance Mode:** A fully self-contained local pool hosted on the installation ISO or local filesystem (`file:/var/cache/mitranet/repo`), enabling zero-internet installations and air-gapped rollouts.
   - **Online Production Mode:** Synchronized upstream repository providing continuous security advisories and MitraNet feature updates over HTTPS.
4. **Zero FreeBSD Intrusion:** No `.pkg` format, FreeBSD `pkg-ng` metadata, or foreign ELF binaries may reside in the repository pool.

│           └── binary-all/

## 3. Package Metadata & Indices Generation

Indices are generated reproducibly using `apt-ftparchive` or `reprepro`:

1. **`Packages` Index:**
   Generated by inspecting every `.deb` file in the component pool:
   ```sh
   apt-ftparchive packages pool/main > dists/rinjani/main/binary-amd64/Packages
   gzip -9c dists/rinjani/main/binary-amd64/Packages > dists/rinjani/main/binary-amd64/Packages.gz
   xz -9c dists/rinjani/main/binary-amd64/Packages > dists/rinjani/main/binary-amd64/Packages.xz
   ```

2. **`Release` Index:**
   Aggregates SHA-256 and SHA-512 checksums of all `Packages` files:
   ```sh
   apt-ftparchive release dists/rinjani > dists/rinjani/Release
   ```

3. **GPG Signing (`InRelease` / `Release.gpg`):**
   ```sh
   gpg --default-key "$MITRANET_GPG_KEYID" --clearsign -o dists/rinjani/InRelease dists/rinjani/Release
   gpg --default-key "$MITRANET_GPG_KEYID" -abs -o dists/rinjani/Release.gpg dists/rinjani/Release
   ```

## 4. Native Debian Package Quality Standards

All MitraNet-built Debian packages (`mitranet-*.deb`) must comply with the following standards:

### A. Metadata Integrity
- **Package Name:** Lowercase alphanumeric with hyphens (`mitranet-core`, `mitranet-network-engine`).
- **Version:** SemVer format with Debian packaging revision (`1.0.2-1~deb13u1`).
- **Architecture:** `amd64` (for compiled components) or `all` (for pure Python/scripts).
- **Maintainer:** `MitraNet Core Team <support@mitranet.id>`.
- **Dependencies (`Depends`):** Explicitly declared against Debian Trixie library packages (e.g., `python3 (>= 3.13)`, `nftables (>= 1.1.0)`, `iproute2 (>= 6.12)`).

### B. Filesystem Placement
- Binaries: `/usr/sbin/`, `/usr/bin/`
- Configuration: `/etc/mitranet/` (marked as `conffiles`)
- Systemd Units: `/lib/systemd/system/` or `/usr/lib/systemd/system/`
- Documentation: `/usr/share/doc/<package>/`
- State & Runtime: `/var/lib/mitranet/`, `/run/mitranet/`

### C. Security & Maintainer Scripts
- **Strictly No Arbitrary Sudo/Root Shells:** Maintainer scripts (`postinst`, `prerm`, `postrm`) must run with `set -e` and perform only minimal service reloads or user creation.
- **File Permissions:** No setuid/setgid binaries permitted unless strictly mandated and capability-bound via `setcap`.
- **Immutable Conffiles:** User-modified `/etc/mitranet/config.json` must be preserved across upgrades via dpkg conffile prompt or three-way merge.

## 5. Rollback, Atomic Upgrade & Recovery Strategy

MitraNet integrates Debian package transactions with Phase 1F Transaction & Recovery Engine:

1. **Pre-Upgrade Snapshot:** Before executing `apt upgrade`, the system captures a configuration snapshot (`/var/backups/mitranet/pre-upgrade-snapshot.json`) and system state.
2. **Atomic Verification:** Following package installation, the post-installation health check probes:
   - Systemd units: `systemctl is-active mitranet-core`
   - Network state: `ip link`, `ip route`, `nft list ruleset`
3. **Automated Recovery:** If health checks fail within the grace period (30 seconds), the system rolls back package states (`dpkg --rollback` / reinstallation of previous version from local pool cache) and restores configuration.
